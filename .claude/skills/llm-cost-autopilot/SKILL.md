# LLM Cost Autopilot

A routing layer in front of OpenAI, Anthropic and a local Ollama model. Callers send an
OpenAI-style request to `POST /v1/completions` and never choose the model. For each request:

1. A scikit-learn classifier assigns a complexity tier: 1 simple, 2 moderate, 3 complex.
2. `config/routing.yaml` maps the tier to a model.
3. A sample of requests (default 10%) is re-run on GPT-4o by a background worker and scored.
4. Failures are escalated and logged, and each one becomes a training example. Retrains are
   gated, so a retrain that lowers accuracy is rejected.

Savings are always measured against `baseline_model` (GPT-4o), **net of what verification costs**.

## Repo layout

| Path | What it is |
|---|---|
| `config/models.yaml` | Model registry: provider, model_id, $/1M input and output tokens, avg latency, quality tier, `baseline_model` |
| `config/routing.yaml` | Tier → model map, fallbacks, `min_confidence`, verification (reference/judge model, `sample_rate`, per-task thresholds), feedback (retrain interval, `max_cv_drop`) |
| `data/labeled_prompts.jsonl` | 214 hand-labeled prompts (`prompt`, `tier`, `verified`), generated by `scripts/make_dataset.py` |
| `src/cost_autopilot/` | `cli.py` (entry point), `engine.py` (route → call → verify → escalate → feedback), `classifier.py`, `features.py`, `verifier.py`, `providers.py`, `api.py`, `worker.py`, `db.py`, `report.py`, `mock.py` |
| `dashboard/app.py` | Streamlit dashboard |
| `var/` | Runtime state (gitignored): `autopilot.db` (SQLite), `requests.jsonl`, `classifier.joblib`, `classifier_report.json` |
| `results/` | `cost_savings_report.md`, `case_study.md`, `stats.json`, charts, baseline CSVs, dashboard screenshot |

## Setup (once per checkout)

```bash
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -e ".[dashboard,dev]"
autopilot train
pytest -q                          # expect all tests to pass, offline
```

Real runs need `OPENAI_API_KEY` and `ANTHROPIC_API_KEY` in the environment or `.env`, plus Ollama
with `llama3.1:8b` for the tier-1 model. Never print, echo or commit keys. If there are no keys, set
`AUTOPILOT_MOCK=1` and **tell the user that mock numbers demonstrate the plumbing and say nothing
about real quality or savings.**

## Commands

```bash
autopilot train [--kind logreg|rf]          # train the classifier on data/labeled_prompts.jsonl
autopilot baseline [--models a b]           # 10 prompts x each model -> results/baseline_*.csv (checks providers)
autopilot loadtest -n 1000                  # in-process load test + retrain + report
autopilot loadtest -n 500 --url http://localhost:8000   # against a running API
autopilot loadtest -n 1000 --spread-days 14 # MOCK ONLY: back-dates requests so the time charts have shape
autopilot serve [--port 8000]               # FastAPI
autopilot worker                            # background verification + hourly retrain check
autopilot drain                             # process the verification queue once
autopilot retrain [--force]                 # retrain from feedback (still gated)
autopilot report                            # rebuild results/cost_savings_report.md from the db
autopilot stats                             # JSON savings summary
streamlit run dashboard/app.py              # dashboard on :8501
docker compose up --build                   # api + worker + dashboard (mock by default)
```

## API

- `POST /v1/completions`: `{"messages": [...]} ` or `{"prompt": "..."}`. Optional
  `routing.verify`: `auto` (sampled, async) | `always` | `sync` (inline only if
  `routing.latency_budget_ms` allows) | `off`. The response carries a `routing` block with
  `selected_model`, `served_by`, `tier`, `confidence`, `reason`, `cost_usd`, `baseline_cost_usd`,
  `saved_usd`, `verification` and `escalated`.
- `GET /v1/requests/{id}`: the audit row. `escalated_text` holds the better answer after a failed check.
- `GET /v1/models`, `GET /v1/stats?days=N`, `GET` / `PUT /v1/routing-config`, `POST /v1/retrain?force=true`, `GET /health`.

## Common tasks

**Swap a tier's model.** Edit `tiers:` in `config/routing.yaml`, or
`PUT /v1/routing-config {"tiers": {"1": "claude-haiku"}}`. Names must be keys in `models.yaml`;
unknown names are rejected with a 422.

**Add a model or update prices.** Add an entry to `config/models.yaml` (provider: `openai`,
`anthropic` or `ollama`). Prices are USD per 1M tokens. Look up current list prices before changing
them, and note the date in the file's header comment. Run `autopilot baseline --models <name>` to check it.

**Tune verification.** `verification.sample_rate` is the main lever. Every verified request pays
for the reference answer again, plus a judge call for summarization and general tasks. The report's
"What verification costs" table projects net savings at 5–100% sampling from the actual traffic. Use
it to recommend a rate. Don't recommend 100%: in tests it made total cost higher than the baseline.

**Improve the classifier.** Add or relabel rows in `scripts/make_dataset.py` (keep the tiers
balanced), run it, then run `autopilot train`. Report the 5-fold CV accuracy and the
`under_routing_rate`, not just the held-out split. Under-routing is the error that costs quality.
All shipped labels are `verified: false`. Mention this if someone treats them as ground truth.

**Investigate escalations.** Query `var/autopilot.db`:
`SELECT task_type, original_model, COUNT(*), AVG(quality_gap) FROM escalations GROUP BY 1,2`.
If escalations cluster in one task type, consider changing that task's threshold or routing it a
tier higher. If they cluster in one model, consider remapping that model's tier.

## Reading the numbers

- Lead with **net cost reduction** (`net_cost_reduction_pct`), which subtracts the cost of
  verification. Gross reduction overstates the savings.
- **Quality parity** is the share of *verified* cheap answers that met the bar against GPT-4o. It
  comes from a sample and measures agreement with GPT-4o, not correctness.
- **Escalation rate** is a share of verified requests, not of all traffic.
- A retrain with `promoted: false` was rejected by the gate. That is the system working. Explain that
  the failure examples probably aren't learnable from the prompt text.
- A dashboard banner saying "Simulated data" means `AUTOPILOT_MOCK=1`. Never present those numbers as
  real results.

## Rules

- Don't commit `.env`, `var/` or API keys.
- Don't use `--spread-days` on real traffic. It rewrites timestamps (the CLI refuses unless mock mode).
- Before quoting savings outside the repo, run a real (non-mock) load test, and say how many
  requests and what sample rate it used.
